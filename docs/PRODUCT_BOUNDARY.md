# FlowGrid Agent Memory：产品边界

## 一句话定位

把 Agent 的原始交互编译为带来源、时间、状态和治理边界的可用记忆，并在有限上下文中返回可核查的当前证据。

## 继承什么

- 代码底座：FlowGrid AML Retriever v1.1（基线提交 `cdae7dbd38d73eda33793b30017559bdfb75eff5`）。
- 从 FlowGrid Core 吸收：判断状态、来源链、时间有效性、替代与撤销、审计门。
- 从 Qwen MemoryAgent 吸收：模型辅助抽取与面向 Agent 的记忆使用经验，但模型保持可替换。
- 从 AWS Memory Runtime 吸收：运行时状态恢复与持久化经验，但云服务保持可替换。

## 核心内与适配层

核心内：原始事件、候选记忆、记忆治理、当前状态解析、证据检索、上下文编译。

适配层：AML Add/Search、MCP、REST、模型抽取器、存储后端、云部署。

## 不可破坏的 FLG 记忆哲学

- 记忆的目标是保持判断连续与安全续接，不是无差别保存聊天或提高召回数量。
- 原始证据、Agent 派生记忆与当前有效状态必须分层，任何摘要或抽取都不能自动成为正式真相。
- candidate、confirmed、inferred、unknown、superseded、rejected、deleted 必须保留不同语义。
- 普通续接只使用当前有效、与行动相关且数量受限的记忆；已否决、被替代或删除的方向不得复活。
- 每条当前结论都必须能逐层回到来源、时间、权限与状态变化链。
- 用户或明确授权的治理规则拥有确认权；Agent 的提议不能静默提升为用户判断。

通用化增加的是记忆类型、作用域、宿主与适配器。它不能削弱上述内核语义，也不要求照搬 FLG Core 的文件布局、CLI 或项目账本形态。

## 首期明确不做

- 不把 FlowGrid Core 改造成通用 Agent Memory。
- 不围绕 AML 题型硬编码产品逻辑。
- 不绑定 Qwen、AWS、CockroachDB 或任何单一厂商。
- 不先做图数据库、管理后台、计费系统或通用 Agent Runner。
- 不把“召回到文本”等同于“当前记忆有效”。

## 首期成功标准

1. 原始事件可追加且可追溯。
2. 可从事件生成候选记忆，并区分事实、偏好、事件、程序和判断。
3. 记忆可确认、替代、删除，检索能识别当前有效状态。
4. Search 返回排序结果、原始证据和状态依据。
5. 可在 token 预算内编译 Agent 上下文。
6. 现有 AML Retriever 回归测试不退化。
